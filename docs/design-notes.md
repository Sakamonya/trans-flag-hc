## 一、正式规格

| 位置 | 色值 | RGB | HSL | 相对亮度 |
|---|---|---|---|---|
| 粉（第 1、5 条） | `#FFA6FF` | 255, 166, 255 | H300° S100% L83% | 55.8% |
| 蓝（第 2、4 条） | `#0090FF` | 0, 144, 255 | H206° S100% L50% | 27.2% |
| 中轴（第 3 条） | `#383838` | 56, 56, 56 | H0° S0% L22% | 4.0% |

结构：粉—蓝—灰—蓝—粉，五条等宽，上下对称，旗比例 3:5。
对比度（WCAG 2.1）：粉/中轴 **6.78**，蓝/中轴 **3.59**，粉/蓝 **1.89**。
经典版（1999）同口径：1.87 / 1.80 / **1.04**。

## 三、被否决的方案（连同数据）

### 1. 「数字彩蛋」版：蓝 `#1999FF`、中轴 `#1F1F1F`

原包里流通的成品图实际用的是这一套色值，但 `scene_preview.png` 又用的是定稿版色值——**预览与成品不是同一面旗**。这是本次重建的直接原因之一。

按 CIEDE2000 计算与定稿版的色差：

| 通道 | 彩蛋版 | 定稿版 | ΔE00 | 判定 |
|---|---|---|---|---|
| 蓝 | `#1999FF` | `#0090FF` | **2.95** | 接近不可辨（JND≈2.3） |
| 中轴 | `#1F1F1F` | `#383838` | **7.94** | **明显可辨** |

也就是说：蓝那一步确实接近无损，但**中轴那一步不是「肉眼几乎不可辨」**。原来的说明把两处并列成同一量级，这一点不准确。（旧文档里的 ΔE 数字未注明公式，此处统一按 CIEDE2000 重算，公式见 `tools/flagkit.py` 的 `delta_e()`。）

用户 2026-10-08 决定：以定稿版为唯一正式规格，彩蛋版不进仓库。想复活它的人可以 fork——改 `tools/flagkit.py` 两行即可。

### 2. 今日日期版 `#FF10FF / #2026FF / #080808`

与定稿版色差 ΔE00 分别为 19.0 / 31.8 / 13.7，肉眼明显。弃。

### 3. 中间态 `#FAA8D9 / #2CB3FC / #6B6B6B`

与定稿版 ΔE00 为 8.3 / 11.9 / 17.7。中间态卸掉了暗轴的气势，又没拿回粉彩的柔和，两头不靠。弃。

### 4. 给正式规格加一圈白描边来救深色底

无效。描边只包住旗子外沿，救不了中间那条被背景吃掉的中轴。正确解法是改中轴本身（见下节）。描边版仍然保留，用途是**让旗子与背景之间有边界**，不是让中轴可见。

## 四、深底亮轴变体怎么来的

问题：GitHub 深色底 `#0D1117` 上，中轴 `#383838` 与背景的对比度只有 **1.61:1**，中轴基本消失，五条被读成四条。

求解：在 `#0D1117` 上扫描全部灰度，对每个候选值计算它与「背景 / 粉 / 蓝」三条相邻边界的对比度，取**最弱那条最大化**的解。

```
argmax_g  min( contrast(g, #0D1117), contrast(g, #FFA6FF), contrast(g, #0090FF) )
```

结果 `#525252`（L32%）。中轴与背景的对比度从 **1.61 → 2.42**；换句话说，此时三条相邻边界
（对背景 / 对粉 / 对蓝）里最弱的一条也有 **2.39**。

注意这是**变体，不是正式规格**。浅色底上请用定稿版；亮轴变体只在深色 UI 里用。
算法实现在 `tools/flagkit.py` 的 `solve_dark_axis()`，换背景色重跑即可。

## 五、构建与改色

```
tools/flagkit.py        调色板、色彩公式（WCAG 对比度 / CIEDE2000）、排版与绘图原语
tools/build_assets.py   旗帜 SVG/PNG、尺寸套图、描边、单色、徽章
tools/build_previews.py 全部效果图
tools/verify.py         一致性校验（按像素比对色值）
```

改色只有一步：改 `tools/flagkit.py` 顶部的 `PALETTE`，然后

```bash
python tools/build_assets.py
python tools/build_previews.py
python tools/verify.py
```

`verify.py` 会逐张打开成品图抽样像素，确认它们等于 `PALETTE`，并检查 SVG、网页默认值和文档是否同步。哪一处忘了改都会报错。

字体依赖：中文用系统「等线」，拉丁与数字用 Segoe UI，等宽用 Consolas。换到 Linux / macOS 构建时需要替换 `flagkit.py` 里的字体路径。

## 六、已知限制

1. **深色底上中轴仍会变弱**，即使亮轴变体也只是把最弱边界做到 2.42:1，远低于正文可读性标准。这面旗的定位是图形标识，不是可读文本。
2. **24px 以下**（旗宽小于 24px）五条开始并拢。图标场景建议只用三条，或改用单色版。
3. **单色版的条纹缝隙是按高度 1% 固定比例**切的，深色底上用白色版、浅色底上用粉色版，反了会糊。
4. **CIEDE2000 数值依赖 sRGB 假设**，未做显示器色域管理。印刷前请按 ICC profile 自行转换。
5. 布面实物图是**程序化渲染**，不是实拍，也未做物理正确的布料模拟——它的用途只是验证「明度扰动之后结构是否还在」。
